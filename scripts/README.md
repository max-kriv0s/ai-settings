# scripts

Скрипты синхронизации общих настроек с настройками инструментов.

## Архитектура sync

Репозиторий хранит общие правила в YAML-файлах. Эти файлы не являются
tool-specific конфигами: они описывают намерение один раз, а `sync.py`
маршрутизирует его по инструментам.

Справочник допустимых инструментов живет только в `scripts/sync.yaml`.
В остальных YAML-файлах верхнеуровневый `tools` не дублируется.

Каждый настраиваемый раздел начинается с `enabled` и `tools`:

```yaml
read_policy:
  enabled: true
  tools:
    - all
```

`enabled: false` отключает раздел. Значение `all` понимает только `sync.py`: он
разворачивает его во все конкретные инструменты из `scripts/sync.yaml`.

Если в YAML указан инструмент, которого нет в `TOOL_SCRIPTS`, `sync.py` должен
завершиться ошибкой. Это защищает от молчаливого пропуска правил.

Порядок работы:

1. `sync.py` читает общие YAML-файлы. Хуки - из всех yaml в `hooks/`, по одному
   на guard; остальные разделы - из своего файла в `CONFIG_FILES`.
2. `sync.py` собирает отдельный `AgentSettings` для каждого инструмента.
3. В `AgentSettings` попадают только правила, которые относятся к этому
   инструменту: напрямую или через `all`.
4. `sync.py` находит adapter в `TOOL_SCRIPTS` и передает ему уже готовый
   per-tool state.
5. Adapter (`tools/codex.py`, `tools/claude.py`, `tools/zed.py`, `tools/pi.py`)
   ничего не знает про `all` и другие инструменты. Он получает только свои
   `agents`, `skills`, `permissions`, `hooks`, `mcp`, `plugins` и рендерит их в
   формат своего клиента.

`AGENTS.md` тоже проходит через эту модель. Каждый adapter сам решает, как
подключать общий файл: symlink, include, `@AGENTS.md` или другой механизм
конкретного инструмента.

## Проверки

Не создавать `__pycache__` и `.pyc`: все команды запускаются с `-B`.

```bash
task test   # smoke-проверки guard-ов: команда идёт на вход, ответ сверяется
task plan   # план синхронизации, ничего не меняет
```

`task test-plan` перегенерирует превью-guard-ы и проверит их, не трогая боевые
файлы. Это и есть проверка синтаксиса: скрипт, который не разбирается, не
запустится.
